# Proposal: Glass-Pipe Followups — Parameter Authority & HF Profile Sync

**One-line summary**: Give the proxy authoritative ownership of sampling parameters on auto-routed calls (R17) backed by a build-time **filesystem scanner** that reads GGUF metadata and per-file Hugging Face sampling recommendations (R18), surface the substitution via a new `event: kinver.proxy.params_replaced`, and register the 4R pre-merge review fan-out as a tracked follow-up. Carry-over cleanups 1–3 are already shipped and tested.

## Intent (Why)

- **R17**: Today (`routes.py:445–490`) the Glass-Pipe client-wins pattern fills *gaps* the client left. When the proxy picks the model — either via explicit auto-routing (`requested_model == "auto"`, parsed at `routes.py:158` and resolved at `routes.py:493`) or the dream/soul fast-path (`routes.py:254–298`) — the proxy owns the model selection, so it should own sampling defaults too; otherwise the client tunes parameters for a model it never selected. R1 client-wins still applies for direct calls.
- **R18**: A speculative HF model_id list leads to confidently wrong profiles for models the operator never installed. Sourcing profiles via a **build-time filesystem scanner** (reads GGUF header metadata from actual files, fetches HF only for operator-declared model_ids) makes parameter authority grounded in reality, deterministic at runtime, and offline-startable. The proxy's target backend is **llama.cpp / GGUF**.

## What Changes

### R17 — Model profile authority (auto-routed mode)
- **Trigger**: auto-routed mode (`requested_model == "auto"`, detected at `routes.py:158` and `routes.py:493`) OR dream/soul fast-path (`routes.py:254–298`). Both are cases where the proxy owns the model pick.
- When triggered: proxy OWNS the **full R11 field set** — `temperature`, `top_p`, `max_tokens`, `thinking_budget_tokens`, `seed`, `top_logprobs`, `response_format`, `n`. Client values are NOT consulted. No opt-out header, no per-client override.
- When direct (client picked model): R1/R7 client-wins unchanged.
- Emit a new top-level `event: kinver.proxy.params_replaced` (the 4th proxy-injected event type, peer to `kinver.proxy.status`, `kinver.proxy.tool_stripped`, `kinver.proxy.audit_halt`) carrying the values actually forwarded so UIs can surface the substitution. Standard OpenAI clients ignore unknown event types.

### R18 — Model profile sync (filesystem scanner + per-file HF lookup)
- **Source of truth**: the actual GGUF files on disk. No speculative model_id list.
- `config/local_models.yaml` — operator-declared **path → hf_model_id** mapping. Every entry MUST point to a real file.
- `config/model_profiles.yaml` — generated by the scanner, checked into the repo, loaded at startup (zero runtime HF calls).
- `tools/sync_model_profiles.py` — scanner CLI:
  - Walks each declared path, **verifies the file exists**, reads GGUF header metadata (`general.architecture`, `*.context_length`, `general.file_type`, `general.name`, etc.)
  - For each `hf_model_id`, fetches the HF model card and extracts recommended sampling parameters
  - Combines: GGUF metadata (technical facts) + HF sampling (creative direction) + operator `overrides:` (deployment tuning)
  - Writes `config/model_profiles.yaml`
  - Subcommands: `sync` (write), `sync --check` (drift = filesystem change OR HF card update for a known model_id), `sync --watch` (hot-reload draft, runtime proxy still loads once at startup)
- **Unparseable handling**:
  - HF card unparseable for a known model_id → SKIPPED AND LOGGED (no profile for that file; runtime uses intent-aware fallback)
  - File missing or unreadable → ERROR (operator declared a path that doesn't exist — must be fixed before sync succeeds)
  - GGUF metadata missing critical fields (architecture, context_window) → ERROR (can't derive a profile without context_window for the headroom calculation)
- **CI gate**: `sync --check` is a HARD BLOCK in CI. Drift (filesystem change, removed file, or HF card update for a known model_id) fails the build.
- `max_tokens` derived as `context_window * 0.9` (10% headroom from GGUF metadata), overridable per-deployment in `overrides:`.
- **Unknown-model fallback**: intent-aware — two rows keyed on `intent=code, model=*` and `intent=chat, model=*`.

Run `review-readability`, `review-reliability`, `review-resilience`, `review-risk` against the full diff before merge. Tracked as a follow-up task; not code.

## Approach

**Profile-owned, not client-owned, when the proxy picks the model.** R18 supplies the authoritative profile table — the scanner reads GGUF metadata from actual files (ground truth for architecture, context_window) and fetches HF per declared model_id for sampling recommendations (creative direction). R17 swaps `parameters.setdefault(...)` for `parameters = profile[route.model_key]` exclusively in auto-routed mode, emits `params_replaced` so the substitution is observable, and keeps R1/R7 client-wins untouched for direct calls. Build-time scanner + runtime load makes the proxy deterministic at runtime and offline-startable.

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Auto-routed clients that relied on sending `temperature` silently lose control. | Med | `params_replaced` status event surfaces the substitution; documented in CHANGELOG as a deliberate authority shift. |
| HF card unparseable for a declared model_id → profile gap for that file. | Med | Skip-and-LOG (not fail); runtime uses intent-aware fallback. |
| Profile drift — filesystem change, removed file, or HF card update for a known model_id. | Med | `sync --check` is a **hard CI gate** — drift fails the build and blocks merge. |
| GGUF metadata missing critical fields (architecture, context_window). | Low | Scanner raises a clear error listing the missing file; operator must fix `local_models.yaml` or the file itself. |
| `tools/sync_model_profiles.py` network dependency in build. | Low | Build-time only; runtime proxy never calls HF. |

## Rollback Plan

R17 + R18 ship in 2 chained PRs (PR1: R18 toolchain + runtime; PR2: R17 + tests + 4R review). Revert the merge commits to roll back. R18 is additive (new config + tool, loaded at startup); reverting restores the prior intent-default table in `routes.py`. No DB migration, no persisted state. The `params_replaced` event type is an unknown SSE event that standard clients ignore — reverting drops the event with no protocol break.
